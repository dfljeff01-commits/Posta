# RUNBOOK 模板 — 监督闭环状态机

> 复制本文件到实例 `$POSTA_HOME/agent/RUNBOOK.md` 并按实例填写。它是监督闭环的唯一事实来源：
> 任何 agent（无论哪个对话、上下文是否新鲜）在巡查时按此执行，不依赖对话历史。

版本：v0（实例化时填日期）

## 一、角色矩阵

| 角色 | 承担者 | 权限边界 |
|---|---|---|
| CTO / 任务发起方 | （填写） | 拆任务、写指令、终审裁定、授权额度与删除 |
| 人 | （填写） | 转达终审请求、代裁（可授权监工代裁）、处理升级事件 |
| 监工 | （填写，如 ZCode 巡查） | 派发、复活、审核、代裁（须落盘 ADJUDICATION）、记录一切手动动作 |
| 执行者 | （填写，注册表中的 cli 类成员） | 按指令执行、边做边记 PROGRESS、如实交付 |
| 复核者 | （填写） | 只读复核，不冒称执行者 |

## 二、每轮巡查动作

1. 运行信箱扫描器（`tools/dispatchd.py`），播报新包裹（分类/路由见脚本）。
2. 对照登记表（§六）检查 status=running 的任务：进程存活、日志增长、PROGRESS 勾选进展 → 2~3 句播报（引用原文）。
3. 交付目录出现齐全交付物 → 执行 §三审核。
4. 所有播报结尾注明：待授权派发 / 执行中，未经确认不越权。

## 三、审核清单（按实例任务类型裁剪）

通用项：

- [ ] 交付包齐全（报告 / 状态文件 / 清单 / 证据）
- [ ] 状态文件结构化字段与报告叙述一致
- [ ] 冻结哈希未被触碰（checkout HEAD/worktree clean/基线校验和）
- [ ] 无授权范围之外的写入

任务特有项（实例自行维护，建议包含）：

- [ ] 单次执行纪律：冻结后仅执行一次，未在运行后修改期望
- [ ] 资源终态：按精确 ID 停止并独立确认、卷保留、删除范围与授权逐条相符
- [ ] 保密纪律：凭据不出现在任何公开工件

## 四、裁决与返工循环

- **PASS**：VERDICT 落盘，播报"监工审核通过，待 CTO 终审"。监工 PASS ≠ 终审通过。
- **FAIL**：写 FIX-DIRECTIVE（逐条问题 + 修复要求 + 禁止事项）→ 续接会话返工（`-c`）。
- **返工上限 3 轮**。升级条件（停止自动循环并叫人）：
  1. 执行者报资格冲突（等人裁定）
  2. 授权范围外的写入/删除/资源异常
  3. 连续两轮同因失败（说明是指令/环境缺陷）
- **复活纪律**：进程提前退出且未交付 → 诊断死因 → 续接复活，次数不限但每次登记死因。
- **代裁纪律**：被授权代裁时，每项裁定落盘 ADJUDICATION 文件（裁定/理由/限制/待追认）；
  代裁不得突破任务指令的授权范围。

## 五、启动机制教训（模板，实例按需增删）

- 长任务用托管后台任务（退出自动唤醒监工），**不要**依赖从自动化 shell 里启动的 tmux 守护进程（会被进程组回收）
- 无头模式权限请求会被 auto-reject：在任务目录放项目级配置做最小放行，写权限保持默认拒绝
- 人类围观：`tail -f <任务目录>/session-live.log`；历史尝试保留为 `session-live.attempt{n}.log`
- relaunch 前确认无同任务残留进程；不杀未知进程

|---|---|---|---|---|
| （示例）example-task-20260101 | running(返工R1) | bg-task-123 | 1/3 | 死因与裁定链摘要 |

## 七、记录纪律

- 一切监工手动动作（派发/复活/核验/代裁）即时补记事件流水账，格式：
  `[补记][DISPATCH|VERIFY|ADJUDICATE] 包裹 → 对象 | 摘要`
- 观察窗（TUI/Web）只反映流水账与包裹 mtime——不补记 = 人看不见
