# PLAYBOOK — 多 Agent 协作协议（实战验证版）

> 脱胎于一个真实的多 agent 软件交付任务全链：从派发到关闭经历 3 次执行中断、1 次资格代裁、
> 1 轮返工、1 次终审与精确收尾，全部机制经实战检验。
> 本文件是"怎么干"的可复用模板；状态机见 RUNBOOK 模板；演进方向见 ROADMAP。

版本：v1

## 零、团队注册（一切的开始）

新流程启动第一步：**让 agent 互相注册认识**——`TEAM_ROSTER.json` 是唯一事实来源，每个成员登记：

- id / 包裹后缀 / 宿主机
- 启动方式：`cli`（可被监工无头派发）/ `desktop-human`（须人工转发）/ `human-relay`（仅信令）/ `unknown`
- 角色分工 / 历史署名（history）/ 资格边界（eligibility）

用途：①信箱路由不再出现 `?`；②资格冲突自查从翻文件变查表；③"不知道执行者是谁"的开局僵局根除。
新成员入伙 = 加一个 JSON 条目；身份未明的成员显式标 `unknown/retired`，不许猜。

## 一、角色矩阵

| 角色 | 承担者 | 权限边界 |
|---|---|---|
| CTO / 任务发起方 | （如某桌面端 agent） | 拆任务、写指令、终审裁定、授权额度与删除 |
| 人 | 人类 | 转达终审、代裁（可授权监工代裁）、处理升级；不参与常规传递 |
| 监工 | 监督 agent（巡查循环） | 派发、复活、审核、代裁（须落盘）、记录一切手动动作 |
| 执行者 | CLI agent | 按指令执行、边做边记、如实交付；无越权写/发布权限 |
| 复核者 | 只读监督位 | 只读复核，不冒称执行者 |

## 二、包裹生命周期（目录即协议）

```
发起方写 DIRECTIVE
  └─ 必须落盘 <任务信箱>/<task-id>-<agent>-<date>/DIRECTIVE.md
     （写在自己工作区 = 未派发；巡查发现后可代为落盘并注明来源）
执行者领取
  └─ PROGRESS.md 边做边记（含开局检查清单、失败记录如实）
  └─ 新写入只在 NEW_TASK 与 NEW_DELIVERY；占用检查后选唯一后缀
交付
  └─ <报告信箱>/<pkg>/delivery[-rN]/：REPORT + STATUS + MANIFEST + 证据索引
审核（监工）
  └─ 同级 review/：审核报告 + VERDICT（实证抽查，不轻信自述）
返工（FAIL 时，≤3 轮）
  └─ NEW_TASK 写 FIX-DIRECTIVE → 续接会话修复
终审
  └─ 同级 final-<date>/：终审报告 + 核查清单
收尾
  └─ 同级 closeout-<date>/：处置回执（删除结果/资源终态/候选哈希）
代裁留痕
  └─ NEW_TASK 内 ADJUDICATION-<编号>（裁定/理由/限制/待追认声明）
```

## 三、已验证的坑与对策（十条，每条都有事故编号）

| # | 坑 | 对策 |
|---|---|---|
| 1 | 自动化 shell 里启动的 tmux 守护进程随调用结束被整体回收 | 长任务用托管后台任务；人要直播就自己开 tmux |
| 2 | 无头模式权限请求 auto-reject，执行者直接放弃 | 任务目录放项目级配置做最小放行（仅指令要求的跨目录只读） |
| 3 | 执行者资格冲突（同品牌署名历史） | 冲突→停→呈报→裁定；自查以文件署名为准，不凭对话记忆 |
| 4 | "一次性执行"额度与返工天然冲突 | 每轮返工随 FIX-DIRECTIVE 显式续授额度（恰一次启动+恰一次执行） |
| 5 | 指令要求删除的凭据文件可能是重跑必需的唯一明文副本 | 删除前做不可逆性评估并显式上报；可裁定暂缓至终审接受后 |
| 6 | 结构化内容走按键/读屏会失真 | 任务书/期望/结论全走文件；按键只做信封；冻结摘要防运行后刷绿 |
| 7 | 手动动作不进事件流 → 人与观察窗都失明 | 一切手动动作即时补记流水账 |
| 8 | 唤醒贵模型处理"没有新包裹"纯属浪费 | 守门脚本先廉价检查，有活才唤起 |
| 9 | 弱模型转述技术内容会丢约束 | 传路径不传内容；摘要只做信封级；原文永远在文件里 |
| 10 | 桌面 GUI agent 是被动的，人打字才动 | CLI 无头形态做管道，GUI 留给人看；协议对 GUI/CLI 一视同仁 |

## 四、关键命令模板

```bash
# 无头派发（新任务）
cd <NEW_TASK> && <executor-cli> run -m <model> \
  --title "<task>" "读取本目录 DIRECTIVE，按开局检查项开始。PROGRESS 边做边记。" \
  > session-live.log 2>&1 &        # 托管后台，勿用自动化 shell 里的 tmux

# 续接（复活/返工）
<executor-cli> run -c -m <model> --title "<目的>" \
  "读取 <FIX-DIRECTIVE|ADJUDICATION>，仅按其执行。" >> session-live.log 2>&1 &

# 人类围观对话存档
cd <NEW_TASK> && <executor-cli>   # TUI 会话列表选对应标题
```

## 五、配置要诀

- 项目级配置只放该任务需要的最小放行项；写权限保持默认拒绝
- 同一"已登记上下文"跨轮续用 `-c` 保身份连续；会话记录即审计史
- 秘钥文件 0600 且绝不进 stdout/报告；启动器用 env 映射而非 `exec env -i KEY=value`（argv 泄露面）
- 每个任务包自带最小放行配置，已被验证为标准件
